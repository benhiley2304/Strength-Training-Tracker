RECONNECT SYNC — MANUAL RELEASE ACCEPTANCE
Implementation based on 52ef9d7; release asset version: strength-training-tracker-v6-sync-5.

Safety / scope
- Use only synthetic accounts and isolated NODE_ENV=test storage. Never use production records, tracker-secrets, user exports, live data-repository writes or force pushes.
- No visual redesign, paid plan, service keep-alive, production deployment or remote push is part of this change. Main agent owns browser QA and release.
- Automated command: npm run check && npm test. Includes isolated local Git repositories and an authenticated Git-backed API lost-push-ack test; no real GitHub credentials needed.

Architecture / expected behavior
- Account-keyed V1 cache remains backward-readable; now stores acknowledged baseState and replacement marker. baseState is never inferred from dirty local content. Detached UI copies make real edits/no-op detection reliable.
- Generic field deltas use the acknowledged baseline, not timestamps. History is indexed by stable workout IDs. Same-ID draft fields/sets merge; independent added set rows are kept; ambiguous concurrent positional deletions need review.
- Completed draft IDs and reset cycles are not resurrected. A different-ID post-finish effort must have meaningful activity and a start after the known finish. Two simultaneous meaningful drafts occupying one session cannot both fit the schema, so both are archived and deliberate review is required.
- Missing-baseline V1 migration favors pending local settings but retains both histories and remote nonempty drafts/values instead of overwriting them with untouched empty local defaults. This is intentionally best-effort: V1 cannot identify every changed field. Unmatched older history or meaningful drafts are held for review if the server revision advanced; only same-revision replay or records started/finished after the cached server acknowledgement timestamp can safely be treated as new additions. No document-wide wall-clock winner.
- Every reconciliation archives both FULL account snapshots in a rolling five-entry :recovery journal before changes. Recovery storage/quota problems block reconciliation, not silently overwrite. Regular online saves can still succeed when device storage is inaccessible, while warning there is no device backup.
- Import replacement is explicit, marked, rollback-backed and not unioned. A newer remote change triggers renewed review. Remote removal of baseline history while local edits are pending is treated as a destructive replacement.
- At most 3 PUT attempts per flush for 409 races (250/500ms delay); no automatic endless race loop. At most 4 extra transient retries (1.5/3/6/12s) per reconnect/edit burst. Initial session/config reads get at most 3 attempts with exponential waits. Each network request is bounded at 90 seconds. Hidden/offline pauses subsequent requests; an already-started request can finish safely.
- Routine statuses: Reconnecting…, Saving your latest changes…, All changes saved. Actual 401 expires the session. No periodic network polling or cold-start keep-alive remains.
- GitStorage still refreshes from the Git remote before every transaction and only returns a changed save after push acknowledgement. Valid authenticated equal PUT is a read-only result even with stale If-Match, recovering lost acknowledgements without extra revisions/commits.

Browser acceptance on isolated test server (port 4000 is suitable)
1. Register/sign in to a synthetic account in two independent contexts. Confirm branding, phone/desktop layout, programme, workouts, dialogs and auth visuals are unchanged.
2. Same-base resume: create one pending field edit offline, close/reopen after reconnect. No Choose-version modal; pending edit appears only AFTER /api/account validates the session, then saves once. Confirm cache has baseState and dirty:false after the acknowledgement.
3. Screenshot-shaped legacy case: synthetic revision5 dirty V1 cache with no baseState, localUpdatedAt 21:16 and server revision6/updatedAt18:15, zero workouts. Include a meaningful local setting and a blank local draft versus a nonempty remote draft. Reopen: local setting and remote effort both retained; both full snapshots in recovery; no blocking export/choose flow.
4. Lost ack: suppress delivery of a successful PUT response, then reopen/retry. An equal account GET clears stale dirty; an equal stale PUT returns the existing revision without another Git commit.
5. Baseline three-way: context A changes workout load/bodyweight; B changes rest default/theme/notes and saves. Reconnect A: only A's changed fields win collisions, B's unrelated changes survive. Repeat with separate completed workouts; both stable IDs remain once each.
6. Completed draft: both contexts start from the same draft. B finishes it, optionally starts a genuinely new effort in that session, and saves. A edits stale notes then reconnects. Old draft does not return; completed history and B's new effort remain. Inspect recovery for stale effort if needed.
7. In-flight races: delay a PUT, edit again; first acknowledgement must not mark the later edit saved. Delay GET, complete a newer PUT, deliver old GET; state/revision cannot regress. Force three consecutive 409s: pending is retained, no modal, no endless timer; Retry sync resumes a bounded burst.
8. Offline/background: turn offline, edit, hide tab, restore network while hidden. No ongoing network loop. Focus/visibility/online flush pending when visible. No unnecessary PUT for reselecting an unchanged preference, re-rendering a blank draft or focusing a clean account.
9. Two tabs sharing storage: A changes bodyweight; B changes rest before receiving A's storage event. Both survive synchronously merging the latest cache. Delayed/stale storage event values do not replace current storage. Another account's key is ignored. An old in-flight acknowledgement cannot undo an adopted newer cache generation.
10. Real session expiration: expire/revoke synthetic cookie, reconnect. Sign-in is required; pending cache remains available to export; account UI is hidden. No account data appears from cache on a cold boot before successful session validation. Do not weaken cookie flags or auth to make testing easier.
11. Corruption: malformed JSON, wrong account ID, invalid state/baseState or invalid journal. Pending/unreadable bytes remain unmodified and exportable; no PUT. Simulate quota failure during journal creation: no merge/overwrite. Normal status must accurately warn when device backup is unavailable.
12. Import: import one selected profile, including intentionally empty/replaced history, then reboot before sync. Replacement marker survives; erased intended history is NOT unioned back. Advance server before syncing import: explicit reviewed confirmation remains mandatory. Multi-profile upload is still refused without one-profile selection.
13. PWA/cold start: install new worker, close/reopen controlled PWA with /api/account delayed/offline. Cached public branded index/skeleton appears immediately, but no private profile appears until auth validates. Known-host boot does not call /api/config. Unknown host handles 503 startup retries; confirmed static HTML404 stays local. Cache Storage contains only public allowlisted shell assets. Network/API/auth responses and cookies/tokens are never cached.
14. Safe update: make pending edits, leave a new worker waiting, press Update & reload. Durable snapshot/journal first; no requirement for successful online save. Reopen validates session then replays pending. Repeat with a locked/corrupt cache: raw bytes and current memory remain in recovery, not erased. If writing recovery fails, activation/reload must stop and ask for export.
15. Upgrade FROM the old already-loaded build: its old button logic cannot be changed by newly deployed files. Let the new worker install, close ALL tracker tabs and PWA windows, then reopen. Never clear site data. Check new VERSION/script is loaded, old pending V1 cache reconciles automatically and no routine choose/export modal reappears. If worker had not installed before close, allow one online visit to install then close/reopen again.

Limits / release notes
- Cached shell accelerates the visible return, not server wake time. Render Free cold-start delay remains; no paid plan or keep-alive was provisioned.
- Journals/rollbacks are local, rolling, unencrypted recovery, not an external backup. Large histories may exceed browser quota, which intentionally requires export/review. Logout removes this account's journal along with cache/rollback, not any other account.
- Newer code can safely journal a locked tab for update; unsupported locked data still needs deliberate recovery after the update. The fix does not reinterpret ambiguous destructive operations as routine merges.
- Automated tests are synthetic. Real mobile/PWA update and production acceptance remain the main agent's responsibility before release.

Reviewer regression additions: inherited blank BW80 draft + profile default81 cannot conflict with a different-ID remote effort; explicit workout BW edits use bwSnapshotEdited or same-ID baseline. Missing-base older histories/drafts absent after online import/reset must be journaled and held, never silently resurrected. Fresh post-ack additions and the zero-history screenshot still auto-reconcile.
